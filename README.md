# АктКреватор — сайт v0.2 (вся логика сервиса, без дизайна)

Реализовано по методологии v0.4 (`07_Методология`) и библиотекам `08_Библиотеки`.

## Что есть

**Вход:** регистрация по логину и паролю, входной тест (около 7 минут) с разбором.

**Тренировочная сессия (12–15 минут), шаги идут строго по порядку, перескочить нельзя:**

| Шаг | Что происходит | С ИИ | Без ИИ |
|---|---|---|---|
| Карточка ресурсов | бюджет, время, что уже пробовали (короткая или полная) | — | — |
| С1 Задача | своя задача или учебная из LIB-11 с «легендой» | проверка формулировки, направления для задач вне сферы | эвристика по формулировке |
| С2 Первые идеи | 3–4 идеи за 2 минуты, фаворит, «почему сработает» | — | — |
| С3 Зеркало | направления ваших идей, облако очевидного, что предложил бы чат-бот, незанятые направления; можно оспорить направление | классификация непонятных идей, ответы чат-бота на вашу задачу | словарь LIB-02, примеры LIB-14 с похожей задачи |
| С4–С5 Диагноз и инструмент | Д0–Д5/Д—, один из 6 инструментов; уровни самостоятельности 1–3; «облегчить» и «сменить» по разу | адаптация задания к задаче | шаблоны LIB-03…07 |
| С6 Своя идея | черновики, до 3 подсказок (на уровне 3 — 2), отказ на «просто дай ответ», самопроверка | коуч с проверкой «не выдал ли готовую идею» | шаблоны LIB-08 |
| С7 Оценка | сдвиг, редкость, гибкость, полезность, авторство, «Беру в работу», «ещё 3 минуты» | рубрика RB1–RB4 | только ресурсы (RB2) по правилам |
| С8 Проверка на прочность | сначала свои причины, потом до 3 возражений, защита, вердикты, 2-й раунд на уровнях 2–3 | критик + отдельный судья | LIB-09 + правила вердикта |
| С9 Маршрут мысли | маршрут одной строкой, «что помогло» | — | шаблон |
| С10 Проверка за 48 часов | план, срок, сигналы «снято / подтвердилось» | адаптация проверки | шаблоны LIB-10 |

**Момент открытия (методология v0.5, `07_Методология/C1_Момент_открытия_v0.5.md`):**
- **рентген идеи** — каждая идея разбирается по механизму: кто действует, что побуждает, какой барьер снимается; человек может поправить разбор;
- **три линзы на задачу** в зеркале — система / поведение клиента / обмен ценностью: главное препятствие без готовых решений; выбранное препятствие ведёт инструмент;
- **эволюция идеи** — отправка создаёт версию (до 4), видно, что менялось;
- **детектор ложного сдвига** — «сдвиг механизма» или «изменилась форма, но не принцип»; сдвиг сессии теперь считается по механизму;
- **лестница выхода из тупика** — «Я застрял(а)»: 4 ступени (что мешает → один барьер → какую часть менять → собрать фрагмент) или честное «закончить без идеи»;
- **перевёрнутая задача** — новый инструмент «цель за целью»; **скрещивание принципов**, когда у человека нет двух редких идей;
- **две шкалы** в оценке — новизна механизма и реализуемость, тип идеи и «доработать слабую сторону»;
- **«вау»-вопрос** на маршруте: «Пришла бы вам эта идея в голову без тренировки?»;
- **второе открытие** — по желанию вернуться к задаче через день (без напоминаний); **профиль привычных механизмов** после 3 тренировок.

**Между сессиями:** вопросы об исходе на 2/7/30 день (в кабинете, не больше трёх сразу, без призыва к тренировке), банк идей по статусам с карточкой идеи, контрольные точки «индекс первой мысли» (LIB-12, 3 минуты, без ИИ), ручная смена уровня, итог месяца, пробный период и «закрытая дверь» оплаты.

**Автоматика:** уровень самостоятельности (3 сдвига из 4 при ≤1 подсказке → выше; 2 сессии без сдвига → ниже), сила инструмента по типу (облегчили → −1, слишком легко → +1), брошенная сессия через 24 часа → идеи в черновики, журнал событий для метрик.

## Как подключить DeepSeek

1. Получите ключ на https://openrouter.ai/keys (на счету OpenRouter должны быть деньги).
2. Откройте файл `site/settings.env` и вставьте ключ сразу после `OPENROUTER_API_KEY=` — без кавычек и пробелов.
3. Проверьте связь:

```
.venv\Scripts\python check_ai.py
```

   Скрипт отправит один короткий запрос и скажет, работает ли ключ.
4. Перезапустите сайт. Пока ключа нет, сайт работает полностью, но на запасных вариантах из библиотек — вверху шагов видно «ИИ не подключён».

Файл `settings.env` содержит секрет: он в `.gitignore`, не пересылайте его. Модель меняется там же (`OPENROUTER_MODEL`). `PILOT_FULL_ACCESS=1` — всё открыто для пилота, `0` — работает пробный период (2 тренировки за 7 дней).

## Запуск на Windows

```
cd site
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python app.py
```

Открыть http://127.0.0.1:5000

- База и секретный ключ сессий создаются в `site/instance/`. Чтобы начать с чистого листа, остановите сервер и удалите `site/instance/actkreator.db`.
- Ключ сессий можно задать через `ACTKREATOR_SECRET`, HTTPS-куки — через `ACTKREATOR_HTTPS=1`.

## Хостинг на Render

**Git-репозиторий — это папка `site`.** Документы проекта (уровнем выше) в него не входят. Библиотеки едут в репозиторий копией в `site/libraries`; оригинал остаётся в `08_Библиотеки`. После правки библиотек и перед коммитом обновите копию (иначе тест `BundledCopyTest` упадёт, а на хостинг уедет старая версия):

```
.venv\Scripts\python sync_libraries.py
```

В `site` лежит `render.yaml` — **бесплатный тестовый вариант**. Шаги:

1. Залить папку `site` в **приватный** репозиторий GitHub. `settings.env`, база и `.venv` в репозиторий не попадут (см. `.gitignore`).
2. Render → New → Blueprint → выбрать репозиторий. Render спросит `OPENROUTER_API_KEY` — вставить ключ.
3. Готово: адрес вида `https://actkreator-xxxx.onrender.com`.

**Ограничения бесплатного плана:** база временная — пользователи и сессии стираются при перезапуске, деплое и после «сна» (сервис засыпает после ~15 минут без посетителей, первое открытие после сна — около минуты). Для теста это нормально.

**Для пилота с сохранением данных** — платный план Starter и постоянный диск. Вручную (New → Web Service):
- **Root Directory** — пусто (корень репозитория = папка `site`);
- **Build Command** — `pip install -r requirements.txt`;
- **Start Command** — `gunicorn --workers 2 --threads 4 --timeout 120 --bind 0.0.0.0:$PORT "app:create_app()"`;
- **Disk** — подключить диск 1 ГБ с путём `/var/data`;
- **Environment** — переменные (для бесплатного теста `ACTKREATOR_DB` не нужна):

| Переменная | Значение | Зачем |
|---|---|---|
| `OPENROUTER_API_KEY` | ваш ключ | ИИ (секрет — только здесь, не в репозитории) |
| `OPENROUTER_MODEL` | `deepseek/deepseek-chat` | модель |
| `PILOT_FULL_ACCESS` | `1` | всё открыто для пилота (`0` — пробный период) |
| `ACTKREATOR_SECRET` | длинная случайная строка | ключ сессий; без него при каждом перезапуске всех разлогинит |
| `ACTKREATOR_HTTPS` | `1` | куки только по HTTPS |
| `ACTKREATOR_DB` | `/var/data/actkreator.db` | база на постоянном диске |
| `ACTKREATOR_ADMINS` | логины через запятую | кто видит страницу `/admin`: проверка хранилища, выгрузка CSV, копия базы |
| `PYTHON_VERSION` | `3.14.7` | та же версия, на которой проходят тесты |
| `ACTKREATOR_LIBRARY_DIR` | не задавать | только если библиотеки лежат в другом месте |

**Ключ OpenRouter и открытая ссылка.** При `PILOT_FULL_ACCESS=1` любой, кто узнает адрес, может зарегистрироваться и тренироваться за ваш счёт (около $0,002 за тренировку). Поставьте лимит трат на ключе в OpenRouter.

## Данные исследования

На бесплатном Render диск временный: после «сна» (15 минут без посетителей), перезапуска и деплоя база стирается — вместе с аккаунтами и незаконченными тренировками. Поэтому данные исследования по ходу каждого шага уходят в **Google Sheets** (модуль `research.py`):

| Вкладка | Строка | Что в ней |
|---|---|---|
| «Входной тест» | одна на попытку | анкета (о себе, последний случай, самооценка), идеи и разбор задачи на 3 минуты, отзыв — те же колонки, что в CSV |
| «Тренировки» | одна на сессию | все шаги тренировки, итоговая оценка, сигнал H4 — те же колонки, что в CSV |
| «Идеи» | одна на идею | тексты первых идей, версий и итоговой; ответы «обычного чат-бота» по той же задаче (для слепой перекрёстной оценки, B6 §3) |
| «Проверка» | — | тестовые записи с `/admin` |

- Строка сессии **обновляется на месте** по мере прохождения, а не дублируется. Если строку всё же пришлось дописать заново (например, сервер перезапустился посреди сессии), у неё тот же `record_id` — берите **последнюю строку** с этим `record_id`.
- Номера участников и сессий — с префиксом базы, например `a3f91c-u4`. После стирания диска номера начнутся с 1, но префикс будет другим, так что люди не перепутаются.
- Логинов, паролей, имён и почты в таблице нет. Тексты идей отключаются переменной `GOOGLE_SHEETS_TEXTS=0`.
- Если таблица недоступна, строки ждут в очереди и уходят при следующем шаге любого участника или кнопкой на `/admin`.
- Строку находит по `record_id` скрипт таблицы (способ А) или запоминает сервер (способ Б). Итоговая анкета пишет участнику «сохранено» только после подтверждения таблицы.

### Подключить таблицу — способ А: Apps Script (проще, без Google Cloud, около 10 минут)

Скрипт живёт в самой таблице и принимает строки от сайта по секретной ссылке с паролем.

1. Создать пустую Google-таблицу (например, «АктКреватор — исследование»).
2. В ней: **Расширения → Apps Script**. Удалить всё, что есть в редакторе, и вставить целиком файл [`apps_script/Code.gs`](apps_script/Code.gs).
3. В строке `const TOKEN = '…'` заменить текст в кавычках на длинный случайный пароль (30+ символов, буквы и цифры). Сохранить (значок дискеты).
4. **Начать развертывание → Новое развертывание** → шестерёнка → **Веб-приложение**:
   - «Выполнять от имени» — **Я**;
   - «У кого есть доступ» — **Все** (без пароля из шага 3 скрипт ничего не запишет);
   - **Начать развертывание** → **Предоставить доступ** → выбрать свой аккаунт. Google предупредит, что приложение не проверено: **Дополнительные настройки → Перейти на страницу проекта** — это ваш собственный скрипт, ему нужен доступ только к этой таблице.
5. Скопировать **URL веб-приложения** (оканчивается на `/exec`).
6. В Render → **Environment**:

| Переменная | Значение |
|---|---|
| `APPS_SCRIPT_URL` | URL из шага 5 |
| `APPS_SCRIPT_TOKEN` | пароль из шага 3 |
| `ACTKREATOR_ADMINS` | ваш логин на сайте (через запятую — несколько) |
| `GOOGLE_SHEETS_TEXTS` | не задавать (`0` — не отправлять тексты идей) |

7. Зарегистрироваться на сайте под этим логином → открыть `/admin` → **Проверить таблицу**: в таблице появится вкладка «Проверка» со строкой, а на странице — «Таблица записала и вернула строку».

8. Самопроверка без сайта: открыть URL из шага 5 в окне инкогнито. Видно `{"ok":true,…}` — доступ настроен верно; Google просит войти — доступ не «Все».

**Если на `/admin` ошибка:**

| Сообщение | Что сделать |
|---|---|
| «Google просит войти» | Управление развертываниями → карандаш → «Выполнять от имени»: **Я**, «У кого есть доступ»: **Все** → Версия: **новая** → Начать развертывание. Если пункта «Все» нет — таблица в рабочем или учебном аккаунте Google, где это запрещено: создайте таблицу в личном аккаунте @gmail.com |
| «тестовый адрес (/dev)» или «похоже на адрес редактора» | в `APPS_SCRIPT_URL` нужен URL **веб-приложения** из «Управление развертываниями», он оканчивается на `/exec` |
| «нет функции doPost» | `Code.gs` вставлен не целиком или не сохранён; после сохранения — новая версия развертывания |
| «неверный токен» | пароль в `const TOKEN` и в `APPS_SCRIPT_TOKEN` различаются (или в скрипте осталась заглушка) — после правки скрипта нужна новая версия развертывания |
| «ответил страницей вместо данных: …» | в кавычках — текст страницы Google; чаще всего это ошибка в скрипте |

После исправления: «Проверить таблицу», затем «Отправить очередь сейчас» — накопленные строки уйдут.

Если правили `Code.gs` позже: **Развертывания → Управление развертываниями → карандаш → Версия: новая** — иначе работает старая версия скрипта, а URL остаётся прежним.

Скрипт сам находит строку по `record_id` и обновляет её — одна сессия остаётся одной строкой даже после перезапуска сервера. Логика скрипта проверяется без Google: `node apps_script/check_code.js`.

### Подключить таблицу — способ Б: сервисный аккаунт Google Cloud (если способ А не подходит)

1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект → **APIs & Services → Library** → **Google Sheets API** → **Enable**.
2. **Credentials → Create credentials → Service account** → **Keys → Add key → JSON**. Файл ключа — секрет: храните **вне папки `site`**, в чаты не отправляйте.
3. Дать адресу сервисного аккаунта (поле `client_email` в ключе) доступ «Редактор» к таблице.
4. В Render: `GOOGLE_SHEETS_ID` — номер таблицы (часть адреса между `/d/` и `/edit`), `GOOGLE_SERVICE_ACCOUNT_JSON` — всё содержимое ключа (можно в base64). Переменные Apps Script при этом не задавать: если заданы обе пары, работает Apps Script.

### Перед тем как звать людей

- `/admin` → «Проверить таблицу» — успешно; «Записей в очереди… ещё не ушло: 0».
- Пройти тренировку самому до конца, включая итоговую оценку, и найти свою строку во вкладке «Тренировки».
- Попросить участников проходить тренировку **за один раз**: если сервис уснёт посреди сессии, аккаунт пропадёт (данные уже отправленных шагов останутся в таблице). Вопросы через 2 и 7 дней на бесплатном плане не дойдут — для них нужен постоянный диск (план Starter, см. выше).

### Страница `/admin`

Только логинам из `ACTKREATOR_ADMINS`:
- **Хранилище** — где лежит база, на постоянном ли она диске, пережили ли данные перезапуск сервера; «Проверить запись» пишет отметку и читает её новым соединением.
- **Google Sheets** — подключены ли, адрес сервисного аккаунта, очередь, последняя ошибка, «Проверить таблицу», «Отправить очередь сейчас».
- **Выгрузка** — архив CSV из базы сервера; по отметке — тексты идей и ответы чат-бота.
- **Копия базы** — полный файл SQLite (с логинами и хэшами паролей — хранить только у команды).

## Тесты

```
.venv\Scripts\python -m unittest discover -s tests
```

187 тестов: библиотеки, правила методологии, каждый шаг сессии, «между сессиями» и сквозной проход всей цепочки в трёх режимах — без ИИ, с ИИ по контрактам, с ИИ, который падает или отвечает мусором. **Настоящий OpenRouter в тестах не вызывается** — используется подставной клиент.

## Живой прогон на настоящем ИИ

```
.venv\Scripts\python live_run.py
```

Три сценария тренировки целиком через DeepSeek, на временной базе (рабочую не трогает): замер ожидания на каждом шаге, число вызовов ИИ, токены и стоимость (около $0,007 за прогон). Результаты — в `exports/live_run_*.json` и `exports/live_run_*.txt`. Разбор первого прогона — `09_Живой_прогон_DeepSeek.md` в папке проекта.

## Выгрузка для исследователей

```
.venv\Scripts\python export_csv.py
```

Создаёт в `site/exports/` (UTF-8 с BOM, открывается в Excel):
- `attempts_*.csv` — входной тест;
- `sessions_*.csv` — тренировки: диагноз, инструмент, сила, подсказки, сдвиг, редкость, рубрика, вердикты, «что помогло», план, исходы;
- `checkpoints_*.csv` — контрольные точки.

Логины и тексты идей тренировок в выгрузку не попадают. Сводка в консоли — сырые доли, без поправок на выборку.

## Честно о границах

- **С настоящим DeepSeek проверено 2026-10-11**: два живых прогона по три сценария (`live_run.py`); ответы пользователя в них заданы сценарием, а не живым человеком.
- **Рубрика полезности и вердикты судьи не откалиброваны** на людях (A4 §7), поэтому показываются как предварительные. Без ИИ полезность оценивается только по ресурсам.
- **Ответы «обычного чат-бота» в LIB-14 — имитация**, их нужно заменить реальными до пилота (см. пометку в LIB-14).
- **Словарь видит не всё:** непривычные формулировки без ИИ остаются «не распознаны».
- **Оплаты нет** — «закрытая дверь» с честным сообщением. Напоминаний во внешние каналы нет (по методологии в пробном периоде их и не должно быть).
- Не готово для публичного запуска: нет восстановления пароля и удаления аккаунта, политики конфиденциальности, проверки на 152-ФЗ, HTTPS-развёртывания.
